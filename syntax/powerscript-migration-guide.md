# PowerScript 迁移指南

本文件用于把 PowerScript 代码迁移到 C# / Avalonia 或其他现代运行时前的分析和设计。它不是逐行翻译规则。

## 1. 迁移原则

1. 先解释源 PowerScript 的业务语义，再设计目标代码。
2. 先识别窗口、用户对象、DataWindow、全局函数、事务对象和外部接口边界。
3. 保留业务规则、校验顺序、错误提示和事务语义。
4. 不把 PowerBuilder 事件模型直接搬成 C# 方法名集合。
5. 不把 DataWindow 简化为普通列表，除非已说明缓冲区、更新、过滤和校验差异。

## 2. 分析步骤

1. 从 `.pbw/.pbl` 导出 `.sr*`，确认 `manifest.json` 和 `report.md`。
2. 选定迁移对象，阅读其继承链、实例变量、事件和函数。
3. 建立调用关系，区分 UI 行为、业务规则、数据库访问和共享工具函数。
4. 标出事务边界、DataWindow 交互和外部依赖。
5. 输出目标设计，再进入代码实现。

## 3. 到 C# / Avalonia 的常见映射

1. 窗口和控件事件映射到 View、ViewModel、Command 和事件处理。
2. 实例变量映射到 ViewModel 状态、服务依赖或局部流程状态。
3. 全局函数优先迁移为可测试服务或静态兼容层。
4. `SQLCA` 事务语义映射到明确的数据库上下文、事务对象和错误处理。
5. DataWindow 逻辑先拆成数据访问、校验、状态管理和界面呈现四部分。

## 4. 输出格式

迁移说明应至少包含：

1. 源对象和文件路径。
2. 源行为摘要。
3. 数据和事务边界。
4. 目标架构位置。
5. 风险点和必须人工验收的业务场景。
