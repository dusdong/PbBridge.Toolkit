# 安装与升级说明

当前 Toolkit 分发版本为 `7.6.0`。

## 安装

1. 将 `PbBridge.Toolkit` 挂载到 `.pbbridge/PbBridge.Toolkit`。
2. 核对 `VERSION`、`manifest.json`、runtime contract 与 template manifest 版本一致。
3. 复制 `pbbridge-project.example.json` 为仓库根 `pbbridge-project.json`，为每个 PBW/PBT 建立 `.pbbridge/workspaces/<id>/workspace.json`。
4. 运行 AST 模板迁移器安装 external project managed files；失败时必须自动回滚。
5. 运行 CLI `doctor`、`toolkit preflight`、`toolkit upgrade-check --repo-root . --workspace <id>` 与 `project adoption check`。

## 从 V7 或更早版本升级

1. 更新 Toolkit/runtime/templates/skills/docs 到 `7.6.0`。
2. V7.2.2 过渡项目先从 canonical Toolkit 入口执行 `pbbridge-template-migrate.ps1 -ProjectRoot . -Plan`，安装原子迁移资产组后再统一使用项目 `scripts/` 入口。
3. 删除非当前 delivery result、cache 与 preflight；非当前输入不能继续 Apply、生成当前 handoff 或加入 V8 session。
4. 将自动化改为消费 V8 compact/full、delivery session 与 typed `nextAction`。
5. 为每个 workspace 重新运行 V8 预检，再通过 `delivery continue` 进入 Apply 或 ApplyIfEligible。
6. 完成 post-apply review、IDE checklist、PowerBuilder Full Build 和业务运行验收。

### 当前 7.6.0 的递增发行与恢复

新正式 tag、唯一名称制品和树外冻结发行记录不可覆盖；历史 7.5.2 替换规则只供原周期审计。执行 `PbBridge.Cli.exe version --identity --repo-root .` 查看产品版本、CLI SHA-256 前12位、实际 Toolkit commit 与完整五元身份；实际 HEAD 和父仓 gitlink 的差异必须保留。完整身份缺失或校验失败时保持 blocked。

`pbbridge-toolkit-update.ps1` 展示旧新完整身份及快照祖先关系。无共同祖先是 latest 单快照容量策略；旧 commit 或源码可重建不能证明原始制品可取回。自动切换前需提供 `-ReleaseRecordPath <旧冻结记录>`、`-RecoveryArtifactRoot <原包本地渠道>`、`-RecoveryExtractionRoot <全新隔离目录>`，核验旧原始 ZIP 的长度、SHA-256、完整身份和可启动入口。缺失、漂移、只有源码或校验失败保持 unavailable/blocked。

`pbbridge-toolkit-upgrade-check.ps1` 可使用上述三个参数及 `-SnapshotPreviewPath <独立预览.json>` 保存同一预览。恢复材料只恢复工具包，不恢复 PBL、源码或 session。升级后逐 workspace 重新生成 readonly-sync/export、baseline 与 V8 preflight；冲突、定制和未知基线保留。旧 session 仅供离线审计，不被当前生产 reader 迁移或继续写回。

### 7.2.3 迁移自举与仓库卫生

`pbbridge-template-migrate.ps1` 与 `PbBridge.TemplateMigration.psm1` 作为 `migration-bootstrap` 原子受管资产组安装。入口默认先解析 `<ProjectRoot>/.pbbridge/PbBridge.Toolkit`；只有 canonical 模板目录中的入口可使用相邻有效 manifest 反向定位 Toolkit。未知自定义、版本错配或候选缺失会在任何项目写入前阻断。

source-hygiene 与 git hygiene 使用当前 workspace 源码的只读 repository graph；每个仓库通过单次 index 枚举和一个 `git cat-file --batch` 会话读取，不扫描无关 submodule，也不改变共享库写回权限。仓库不可读取时必须复核 `formatNoise=incomplete`，不能按 `none` 处理。

### 7.2.2 策略与历史断代升级

readonly-sync 默认发现 `.pbbridge/source-hygiene-policy.json`；显式覆盖使用 `--source-hygiene-policy <path>` 或 wrapper `-SourceHygienePolicyPath <path>`。显式路径缺失或规则无效会稳定失败，不会静默禁用。

普通 Toolkit 快进也需要核验旧原始制品恢复材料，再使用 `pbbridge-toolkit-update.ps1 -Apply`。无共同祖先时，先用本次结果的 40 位 `remoteCommit` 作为 `-TargetCommit` 预检；目标契约有效后，才允许 `-Apply -AcknowledgeHistoryDiscontinuity` detached 切换。`-WhatIf` 不修改 HEAD，本地有共同祖先的分叉无论是否确认都保持阻断。

```powershell
pbbridge toolkit upgrade-check --repo-root . --workspace canyin --wrapper-smoke-scope all
pbbridge delivery close-loop --repo-root . --workspace canyin --object "app.pbl:window:w_example=src/app.pbl.src/w_example.srw" --result .pbbridge/workspaces/canyin/results/delivery-v8/preflight.json
pbbridge delivery continue --from .pbbridge/workspaces/canyin/results/delivery-v8/preflight.json --apply
```

仅有既存业务脏状态或其他 Git hygiene 提醒时，upgrade-check 保持 `status=warning`，默认退出码为 0；需要把 warning 作为 CI 失败时显式增加 `--strict-git-hygiene`，或在 wrapper 中使用 `-StrictGitHygiene`。

### V5 与 V7.2 旧项目

- V5.0.0/V5.0.1 可以从没有 V7 `project.json` 的官方状态直接 Plan；迁移器依据不可变 Toolkit Git 对象的历史 provenance 识别官方 wrapper，也能识别现场仍存在且由项目提交的 Toolkit 指针证明的 3.7.4 官方残留，并从显式参数、可证明的 wrapper 默认值或唯一 PBW 生成候选配置。
- V7.2.0 至 V7.2.3 使用现有 V7 配置直接迁移。
- 两类项目都必须复制 Plan 返回的完整 `nextAction`，继续受 PlanHash、决定集、漂移检查、ShouldProcess、WhatIf 和事务恢复保护；禁止先手工替换 bootstrap 或改写产品版本。
- 对消费项目的批量升级不属于 7.6.0 发布流程，现场 Apply 只在受控副本执行。

非当前 schema 不提供兼容 reader。遇到 `unsupported` 或 `invalid` 时只能重新运行当前 V8 preflight，不能修改旧结果绕过。
