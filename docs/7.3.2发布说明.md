# PbBridge.Toolkit 7.3.2 发布说明

7.3.2 是旧项目升级治理版本。它让仍在使用官方 V5 与 V7.2 Toolkit 的项目直接进入当前 Plan → Decide → Apply 协议，并修正 upgrade-check 对既有业务脏状态的完成度与退出码表达。V8 delivery schema、PB9/x86 写回和人工 IDE 验收边界保持不变。

## 新增与修复

- 从 V5.0.0、V5.0.1 发布标签以及现场项目提交所绑定的 Toolkit 3.7.4 Git 对象重建官方 wrapper 与 legacy migration-bootstrap provenance，同时保存 raw 与 `powershell-text-v1` normalized SHA256；不使用现场工作树文件反向建立官方基线。
- 官方 V5 项目可以从“无 V7 project/workspace config”的原始状态直接 Plan；迁移器从可证明的 wrapper 静态默认值、显式参数或唯一 PBW 生成当前候选配置。
- V7.2.0 至 V7.2.3 继续单步升级到 7.3.2，不要求手工替换 bootstrap、修改 `productVersion` 或绕过 PlanHash、漂移检查和 ShouldProcess。
- V5 已知单文件迁移入口可原子升级为当前入口与模块；未知自定义、版本错配和无法证明来源的 bootstrap 仍会阻断。
- upgrade-check 只根据 `upgradeOwnedChanges[]` 判断 `complete` 与 `ready-pending-commit`；既有且不冲突的业务脏状态只进入 `preExistingDirtyState[]`。
- `pbbridge toolkit upgrade-check` 在仅有 Git hygiene warning 时默认返回 0；`--strict-git-hygiene` 将相同 warning 映射为 warning-only 非零退出码，JSON 分类保持一致。
- 外部项目 wrapper 增加 `-StrictGitHygiene`，只负责转发 strict 策略并传播 CLI 输出与退出码。
- 合成性能数据集缓存缺少 manifest、目录不完整或身份漂移时会从确定性 fixture 安全重建，避免一次中断永久阻断发布门禁。
- comparison baseline 改为在全部场景测量完成后读取，确保基线捕获与候选比较的计时负载一致；性能 schema、相对阈值、噪声下限和绝对预算均未放宽。

## 迁移路线

- V5.0.0、V5.0.1：直接迁移到 7.3.2；允许缺少 V7 配置，混合遗留的 3.7.4 官方资产也可按可验证 provenance 识别，但未知内容仍必须按项目定制协议处理或阻断。
- V7.0.0 至 V7.3.1：直接迁移到 7.3.2，继续使用 schemaVersion 8 的 Plan/Decide/Apply 与 policy schemaVersion 1。
- 不增加 7.3.0 → 7.3.1 专用兼容路径；7.3.0 仅作为现有通用源版本集合的一员。

## 保持不变

- Delivery 与 template migration 继续使用 schemaVersion 8，已有 V8 session 不要求迁移。
- PlanHash、决定集、源与模板漂移检查、WhatIf、ShouldProcess、候选验证、事务恢复和未知定制阻断不放宽。
- PB9 Full Build、GUI 调试、运行场景和业务正确性仍由 PB IDE 与验收人员负责。
- PERF 业务日志比较器、证据生成项目文档、GUI Full Build 自动化和消费项目批量升级不属于本版本。

## 发布门禁

候选包必须通过：

- 相关与全量 .NET 测试、PowerShell/Pester；
- OpenSpec strict、Toolkit entrypoints lint、模板/provenance/版本一致性和 `git diff --check`；
- V5 与 V7.2 自动 fixture；
- 至少一个 V5、一个 V7.2 项目的受控副本 Plan、WhatIf、Apply、no-change 回归；
- 打包后 Windows x86 doctor、release engineering summary 和 pre-push release check。

现场项目原仓库只用于读取版本、配置、受管脚本和必要 Git 状态。所有迁移写入验证都在受控副本执行；7.3.2 发布不开始 `G:\Hangjia` 或 `G:\Langchao` 的批量升级。
