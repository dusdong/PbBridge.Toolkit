# PbBridge Toolkit 2.8.0 发布说明

`2.8.0` 是外部项目效率与提交决策清晰度版本，重点把现有证据链收敛为可执行的提交判断，并降低大型 PB9 项目的日常 readonly sync 成本。

## 新增能力

1. `release-check` 与 `project-health` 输出 `decision`，区分本次变更阻断、历史存量阻断和 Toolkit/配置阻断。
2. 新增 `pbbridge-precommit-summary.ps1`，聚合 Git 改动、drift 解释、共享库 gate、submodule 和 evidence policy，输出提交前短摘要。
3. 新增 `.pbbridge/evidence-policy.json` 策略口径，默认不提交 `project-health.json`、`release-check.json` 和 `pbl-change-intake.json`，提交受管控 `.pbl` 时可保留 `pbl-drift-remediation.json`。
4. `pbbridge-readonly-sync.ps1` 支持 `-IncrementalRefresh`、`-RefreshLibrary`、`-RefreshObjectKey` 和 `-PreviousArtifactsPath`，在已有完整 manifest 基础上刷新指定范围。
5. readonly sync 摘要新增 `SubmoduleSourceMode`；默认按 artifacts-only 口径处理 submodule 源码，显式 `-RefreshSubmoduleSources` 才表示允许刷新 submodule 源码事实源。
6. 新增 `pbbridge-init-shared-libraries.ps1`，根据 `.gitmodules`、共享库 PBW/PBT 和父项目 manifest 生成 `.pbbridge/shared-libraries.json` 草案。
7. `suggest-fixes --code PBV076` 新增 `categories[]` 和 `repairPlan[]`，仍保持只读，不生成 cleaned `.srf`，不自动覆盖源码或 PBL。

## 不变边界

1. 当前正式 PB9 PBL 写回路径仍是 `Windows x86 + PBSpy + PBSDK`。
2. ORCA 仍是 candidate，不升级为 supported。
3. `precommit-summary` 不替代 release-check 发布门禁。
