# 3.12.0 发布说明

`3.12.0` 是 `pbl change-intake` 的轻量化增量版本。它不引入 v4 schema，也不扩大 PB9/ORCA 支持矩阵；重点新增 `pbbridge pbl change-intake --projection-only` 与外部项目 `pbbridge-pbl-change-intake.ps1 -ProjectionOnly`，用于在 PowerBuilder IDE 直接修改 `.pbl` 后，只刷新命中 PBL 的文本投影与 manifest，而不再默认串行执行整条仓库级门禁链路。

## 主要变化

1. `pbbridge pbl change-intake --projection-only` 继续复用 `schemaName=pbbridge-v3-pbl-change-intake`、`schemaVersion=3`；默认 full intake 行为保持不变。
2. projection-only 必须与刷新目标一起使用：至少传入一个 `--refresh-library <glob>` 或 `--refresh-object-key <objectKey>`；外部项目 wrapper 使用 `-RefreshLibrary` / `-RefreshObjectKey` 传递相同语义。
3. projection-only 路径只执行命中 PBL 的 scoped readonly refresh，刷新对应 `.sr*`、manifest/source layout 与对象计数，并清理命中库下已删除对象留下的 stale `.sr*`。
4. projection-only 不再串行执行 `pbl drift-remediation`、`verify`、`report`、`source-hygiene`、`baseline refresh`、`release check` 与仓库级 gate；需要完整门禁时仍使用默认 full intake。
5. 结果 JSON 新增 additive 字段：`projectionOnly`、`requestedLibraries`、`refreshedLibraries`、`refreshedObjectCount`、`changedSourceFiles`、`deletedSourceFiles`、`skippedGlobalChecks` 与 `libraryResults[]`，便于脚本和 AI 助手判断轻量刷新范围。
6. 外部项目 `pbbridge-pbl-change-intake.ps1` 新增 `-ProjectionOnly`，但 wrapper 仍只负责 Toolkit runtime 定位、参数转发、日志落盘和退出码透传，不新增业务判断。

## 推荐升级动作

已经使用 `3.11.1` 的外部项目建议升级到 `3.12.0`，并同步 intake wrapper 与说明文档：

1. 更新 `.pbbridge/PbBridge.Toolkit` 到 `3.12.0` 快照并提交 submodule 指针。
2. 同步 `scripts/pbbridge-pbl-change-intake.ps1`，确认模板版本头与 `template-manifest.json` 都是 `3.12.0`。
3. 如果 PowerBuilder IDE 的修改只影响单个 PBL 或少量对象，优先运行：

```powershell
pbbridge pbl change-intake --project-root . --workspace-path . --projection-only --refresh-library app_main.pbl
powershell -ExecutionPolicy Bypass -File .\scripts\pbbridge-pbl-change-intake.ps1 -ProjectionOnly -RefreshLibrary app_main.pbl
```

4. 如果需要重新跑完整 verify / release gate / source-hygiene / baseline refresh，则继续使用默认 full intake，不要把 projection-only 当作发布前门禁替代。

## 兼容说明

本版保持 V3 additive 兼容：

1. 不修改 `pbbridge-v3-pbl-change-intake` 的 `schemaName` / `schemaVersion`。
2. 不改变默认 full intake 的阶段顺序与 blocked 语义。
3. 不扩大 PB9 `Windows x86 + PBSpy + PBSDK` 之外的正式支持矩阵。
4. 不把 wrapper、skill 或 SharpIDE 变成新的业务规则引擎。
