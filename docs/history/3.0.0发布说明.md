# 3.0.0 发布说明

`3.0.0` 是 PbBridge 的基础架构优先 breaking-major 版本。它冻结 v3 CLI 契约、项目模型 3.0 和写回状态机输出，面向 Toolkit、PowerShell wrapper、SharpIDE、CI 和 AI 代理提供统一 JSON 事实面。

## 主要变化

1. 所有 v3 workflow 固定使用 `schemaName=pbbridge-v3-*` 与 `schemaVersion=3`。
2. 共同 JSON 字段固定为 `generatedAt`、`status`、`stage`、`checks[]`、`evidence[]`、`artifacts[]`、`nextActions[]` 和 `summaryText`。
3. 退出码固定为 `0=success`、`1=execution-failed`、`2=argument-error`、`10=blocked`、`11=warning-only`。
4. `readonly-sync`、`release-check`、`project-health`、`pbl-change-intake` 和 `shared-library writeback-check` 消费统一 `PbWorkspaceModel`。
5. `import-object`、`import-package run` 和 `confirm-object-writeback` 输出统一 `applySessionId`、`stages[]`、`artifacts[]`、`rollbackPlan`、失败分类和下一步动作。
6. PowerShell wrapper 只保留 CLI 调用、路径适配、日志落盘和 JSON/退出码透传；`AllowBlockedResult` 只表示保留 blocked JSON，不改变 blocked 语义。
7. SharpIDE 只读消费 CLI/Core JSON，不承载 PBW/PBT/PBL、shared-library gate 或写回阻断业务规则。

## 迁移提醒

1. 外部项目应更新 `.pbbridge/PbBridge.Toolkit` 到 `3.0.0` 对应提交，并确认 `runtime/cli/win-x86/PbBridge.Cli.exe version` 输出 `3.0.0`。
2. JSON 消费方必须切到 `pbbridge-v3-*`，不要继续断言 2.x 旧 schemaName 或旧输出字段。
3. CI 和 wrapper 必须把 exit 10 识别为业务阻断；exit 1 只用于真实执行失败。
4. 既有项目同步受管模板后，应重新运行 `project-health`、`release-check` 和 `readonly-sync` 生成新契约证据。
5. 字段清单、workflow 专用字段和校验入口见 [V3契约参考](../reference/V3契约参考.md)。

## 已知边界

1. 本版不扩大 PB9/ORCA 支持矩阵。
2. ORCA 仍是 candidate，不是默认或正式 supported PBL 写回器。
3. 本版不新增未准入写回路径。
4. Apply 成功仍不等于 PowerBuilder IDE Regenerate、Full Build 或业务运行验收通过。
