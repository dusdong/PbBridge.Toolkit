# 3.2.0 发布说明

`3.2.0` 是 V3 只读体验层与外部项目落地增强版本。它不改变 v3 基础字段，不引入 v4 schema，不扩大 PB9/ORCA 支持矩阵，不新增未准入写回路径。

## 新增能力

1. `pbbridge project adoption check`：输出 `schemaName=pbbridge-v3-project-adoption-check`，只读检查 Toolkit runtime、CLI/Toolkit/template 版本、wrapper 现状、`.pbbridge/workspaces` 跟踪风险、manifest/source layout 和 shared-library evidence。
2. `pbbridge diagnostics summary`：输出 `schemaName=pbbridge-v3-diagnostics-summary`，聚合 project-health、release-check、readonly-sync、project model、contract validate 和 release engineering summary JSON facts，给出是否可继续修改、DryRun、Apply、提交和发布的结构化结论。
3. Core v3 JSON helper 和 SharpIDE 只读 facade：消费 common fields、checks/evidence/artifacts/nextActions、workspaceModel、stages 和 rollbackPlan；SharpIDE 不解析 PBW/PBT/PBL，也不实现 PowerBuilder 业务规则。
4. release engineering 增加 `releaseAssetHandoff` 和 `release-notes-summary.md`，用于人工发布页和发布资产交接。

## 使用建议

```powershell
pbbridge project adoption check --project-root .
pbbridge diagnostics summary --project-root .
pbbridge contract validate .\.pbbridge\diagnostics-summary.json
```

`project adoption check` 只输出诊断、建议和可审计同步计划，不静默覆盖外部项目本地自定义文件。`diagnostics summary` 只从 CLI/Core JSON facts 推导结论，不从 stdout 文本猜测。

## 边界

1. ORCA 仍为 candidate，不是默认或正式 supported PBL 写回器。
2. Apply 成功不等于 PowerBuilder IDE Regenerate、Full Build 或业务运行验收通过。
3. PowerShell wrapper 仍只负责 CLI 调用、路径适配、日志落盘和 JSON/退出码透传。
