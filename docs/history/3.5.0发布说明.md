# 3.5.0 发布说明

`3.5.0` 是 V3 生产接入与受控写回准备版本。它不改变 v3 共同字段，不引入 v4 schema，不扩大 PB9/ORCA 支持矩阵，不新增未准入写回路径。

## 1. 新增只读入口

1. `pbbridge project adoption check --write-baseline`：显式写出 `.pbbridge/adoption-baseline.json`，用于长期接入审计、比较和建议。
2. `pbbridge project drift check` / `pbbridge project model diff`：比较当前项目模型与 adoption baseline，输出 `schemaName=pbbridge-v3-project-drift-check`。
3. `pbbridge writeback readiness check`：只读评估 DryRun/Apply/Writeback/Verify 前置条件，输出 `schemaName=pbbridge-v3-writeback-readiness-check`。
4. `pbbridge diagnostics bundle verify`：验证 diagnostics bundle manifest、facts、SHA256 和 local-only/redaction 摘要。

## 2. 消费口径

所有新增结果仍使用 `schemaVersion=3` 和 v3 common fields：`status`、`stage`、`checks[]`、`evidence[]`、`artifacts[]`、`nextActions[]`、`summaryText`。blocked 仍返回 exit 10，exit 1 只表示真实执行失败。

PowerShell wrapper、Toolkit skill 和 SharpIDE 只消费 CLI/Core JSON，不解析 PBW/PBT/PBL，不重新实现 shared-library gate、release-check、drift 判定或写回阻断规则。

## 3. 推荐流程

```powershell
pbbridge project adoption check --project-root . --profile standalone --write-baseline
pbbridge project drift check --project-root .
pbbridge writeback readiness check --project-root .
pbbridge diagnostics summary --project-root .
pbbridge diagnostics bundle create --project-root .
pbbridge diagnostics bundle verify --project-root .
```

shared-library consumer、source layout blocking drift、缺失 rollback/re-export/verify 证据或未准入 PB9/ORCA 写回路径都必须以 warning 或 blocked 诊断表达，不静默放行。

## 4. 发布前检查

发布前必须确认：

1. `VERSION`、Toolkit manifest、runtime contract、template manifest 和 CLI version 必须与当次发布目标版本一致（3.5.0 发布时为 `3.5.0`）。
2. `docs/examples/pbbridge-v3-contract/` 包含 3.5.0 golden JSON。
3. `scripts/test-doc-contract-hygiene.ps1 -RequireReleaseEngineeringSummary` 可校验 release readiness。
4. `scripts/build-release-engineering.ps1 -SkipAutonomousGate -RequireToolkitAlignment` 通过。
