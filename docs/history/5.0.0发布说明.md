# 5.0.0 发布说明（历史归档）

`5.0.0` 是 V5 Toolkit 契约硬切版本。`5.0.1` 发布后，本文只作为历史背景保留；所有使用 PB Toolkit 的项目默认升级到最新版，并重新运行当前 `workspace readonly-sync` 或 `source export` 生成 `.pbbridge` facts。

## 关键变化

1. 旧 stdout 完整 JSON 不再作为生产消费面；stdout 固定为 compact summary，完整事实读取 `resultJsonPath`。
2. V5 日常写回主路径收敛为 `pbbridge delivery close-loop` 和 `pbbridge-delivery-close-loop.ps1`；V4/import/writeback 入口保留为专家排障和底层编排能力。
3. `delivery close-loop` 输出 feature-level verdict、跨 PBL batch、对象恢复状态、normalized diff、`performanceSummary`、`slowStages[]`、DryRun/Apply 计数字段和结构化 `nextCommand`。
4. Apply 后 V5 顶层事实包含 `deliveryVerdict`、`canProceedToIdeFullBuild`、`writtenObjectCount`、`sourceMatchesObjectCount`、`formatOnlyDiffCount`、`businessDiffCount` 和 `ideChecklistCommand`；DryRun 未写回对象进入 `pendingApplyObjectCount` 与 `notWrittenObjectCount`，不再计为真实失败。
5. 新增 IDE 验收证据入口：`delivery ide-checklist` 生成 Full Build 清单，`delivery ingest-ide-log` 接收 IDE 日志并输出独立 evidence 与 `mappedFixTargets[]`。
6. DataWindow 校验保持默认离线，显式启用 SQL Server database profile 后可执行表/字段、SQL prepare、参数基础类型和 PBSELECT 风险分级；`datawindow profile init` 生成不含明文密码的 profile 示例。
7. `toolkit upgrade-check` 增加模板差异分类、`upgradeCompletionVerdict`、`upgradeReadyToCommit`、`blockingTemplateChanges[]`、`blockingGitHygieneChanges[]`、`upgradeOwnedChanges[]`、`preExistingDirtyState[]`、`unrelatedDirtyState[]` 和 `performanceSummary`，区分必须合并、已应用、仅需提交 submodule 指针、既有脏状态、Git hygiene 阻断和慢阶段；CLI 默认 `--wrapper-smoke-scope all`，外部项目 wrapper 默认 `-WrapperSmokeScope recommended`，正式验收可显式切回 `all`。upgrade-check 会并行执行 wrapper smoke 与 Git hygiene，`performanceSummary.totalElapsedMs` 表示墙钟耗时，`wrapperSmokeTimings[]` 可定位单个慢 wrapper。
8. 新增 `delivery handoff-summary`、`schema explain delivery-close-loop` 和 Git 换行/index 噪声诊断，降低 Agent 交接和用户解释成本。
9. `managed-artifacts` 不再作为当前生产 source layout；当前导出和 Toolkit wrapper 统一使用 `beside-pbl-src`。
10. 旧 manifest/state、旧 PBIR 头部质量元数据和旧 preflight JSON 只返回当前可诊断错误，不再静默兼容读取。
11. CLI route、help、schemaName 和 grouped command coverage 收敛到 command descriptor。
12. 当前 docs、Toolkit skills、templates 和 release lint 阻断旧兼容入口回流。
13. `pbbridge toolkit entrypoints explain --intent <intent>` 为 Codex 输出 recommended / expert / fallback / reason 入口摘要；`pbbridge object find/export/repair/diff` 对象意图入口用于单对象定位、直接反导出、修复缺失投影和 DataWindow 语义 diff；`object find` 会把 v5 对象索引缓存到 `.pbbridge/cache/object-intent-index.current.json`，current 文件只保存 header、PBL/source root/源码父目录祖先链拓扑签名、manifest 签名、数量、默认对象候选和 generation shard 路径；冷缓存并发构建受跨进程锁保护，只有一个进程 rebuild，其余进程等待后复用已原子发布的 current index，避免 `file exists` / `access denied` 随机失败。精确对象查询按轻拓扑校验按需读取 lookup shard（`shardedIndexLookup` / `lookupShardHit`），模糊查询才读取 object list 并 `linearFallback`，默认源码正文 mtime 变化不触发定位索引重建；compact stdout 顶层直接输出 `cacheStatus` 和 `totalElapsedMs`，完整 JSON 继续在 `performanceSummary.cacheStatus` / `performanceSummary.totalElapsedMs` / `performanceSummary.stages[]` 提供兼容事实。
14. `object diff --semantic` 默认只写最终 diff JSON，不再额外写 `object-diff-baseline-inspect` 或 `object-diff-current-inspect` 中间文件；直接运行 `datawindow inspect` 时仍写 inspect result。
15. `pbbridge performance benchmark` 在一次运行开始时按 scenario 懒加载 `RuntimeBenchmarkContext`，只在需要默认输入时解析 manifest、source roots、默认对象和默认 DataWindow baseline；默认对象 fallback 复用 object intent shard 索引，显式 `--object` 不读取 manifest，避免无关 scenario/iteration 反复扫描。
16. 所有受管外部项目 PowerShell wrapper 都支持 `-Help` 和 `-CliHelp`；`-CliHelp` 直接转发 CLI help，不创建 `logs/*-help` 目录。没有对应 CLI 的本地工具 wrapper 会说明请使用 `-Help`。模板同步脚本从 `template-manifest.json` 的 `recommendedEntrypoints[]` / `expertEntrypoints[]` 自动推导 CLI help 参数，只保留统一 managed wrapper 注入路径和小型特殊覆盖表。

## 升级要求

1. 升级 Toolkit 后重新运行 `pbbridge workspace readonly-sync` 或 `pbbridge source export`。
2. 外部项目日常写回改用 `scripts/pbbridge-delivery-close-loop.ps1` 或 `pbbridge delivery close-loop`。
3. 自动化脚本必须读取 V5 顶层事实和 compact summary 中的 `resultJsonPath`，单对象定位可直接读取 compact 顶层 `cacheStatus` 与 `totalElapsedMs` 做快速观测；不得依赖旧完整 stdout 或 V4 历史字段推断交付结论。
4. 外部项目如残留旧 state，应重新生成当前 facts，而不是执行旧 manifest 迁移。
5. 只需重建单个 `.srd/.srw/.sru` 时，优先使用 `pbbridge object export <pbl:type:name> --out <path>` 或 `pbbridge object repair`，不要先进入完整 workflow。
6. 排查 wrapper 入口时使用 `-Help` 或 `-CliHelp`，不要用 `-?` 作为稳定契约。

## 不变边界

1. 不扩大 PB9/PBSpy/PBSDK/ORCA 支持矩阵。
2. 不把 PBSpyORCA candidate 升级为正式 supported 写回路径。
3. 不替代 PowerBuilder IDE 编译、调试和运行验收。
4. 不承诺跨 PBL 原子事务；跨 PBL feature 只提供 batch 级恢复证据和 feature-level 交付结论。
