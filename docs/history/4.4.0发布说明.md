# 4.4.0 发布说明

`4.4.0` 是写回闭环能力版本，新增 `pbbridge writeback close-loop`，把 source preflight、DryRun、Apply、re-export、normalized diff 和交付结论收敛到一个高层入口。

## 新增能力

```powershell
pbbridge writeback close-loop --object erp.pbl:window:w_order=src/w_order.srw
pbbridge writeback close-loop --object erp.pbl:datawindow:d_order=src/d_order.srd --object erp.pbl:window:w_order=src/w_order.srw --apply
```

1. 未传 `--apply` 时只生成 close-loop plan，不写 PBL。
2. 传入 `--apply` 时，命令内完成 DryRun、Apply、re-export、normalized diff 和 final verdict。
3. 支持重复 `--object`，v1 只允许同一目标 PBL；跨 PBL 输入返回 `argument-error`。
4. 多对象按 `structure -> function -> datawindow -> userobject -> window -> menu -> application -> other` 排序，同类型保持用户输入顺序。
5. 外部项目模板新增 `pbbridge-writeback-close-loop.ps1`。

## 结果契约

新增 `pbbridge-v4-writeback-close-loop`：

- `closeLoopVerdict=dryrun-only|ready-for-ide-validation|ready-with-format-warnings|blocked|failed|business-differs|ide-fallback-required`
- `requestedObjectCount`、`writtenObjectCount`、`sourceMatchesCount`、`formatOnlyDriftCount`、`businessDiffCount`、`blockingIssueCount`
- `pblWritebackCount`、`requiresIdeFullBuild`、`deliverySummaryText`
- `objects[]`：每个对象的 `objectKey`、`sourcePath`、`sourceHash`、`targetPblChanged`、`targetObjectWritebackVerdict`、`normalizedDiffVerdict`、DryRun/Apply/recover 路径和 `nextAction`

## 交付判断

- `ready-for-ide-validation`：可进入 PowerBuilder IDE Full Build。
- `ready-with-format-warnings`：仅格式差异，可进入 IDE Full Build，但需保留 warning。
- `business-differs`：反导存在业务差异，需要先处理源码或 PBL 差异。
- `blocked|failed|ide-fallback-required`：按 `objects[].nextAction` 和 evidence 处理后重新闭环。
