# 3.4.0 发布说明

`3.4.0` 是 V3 质量收口与治理自动化版本。当前 Toolkit 分发版本以 `manifest.json` 的 `toolkitVersion` 为准；本说明固定质量收口口径，避免把阶段性内部重构写成新的 CLI 契约或支持矩阵扩容。

## 关键变化

1. V3 契约实现继续拆分为 workflow registry 与 workflow-specific validator 等清晰边界；对外 `schemaName=pbbridge-v3-*`、`schemaVersion=3`、基础字段和退出码语义不变。
2. 只读诊断保持 `project adoption check`、`diagnostics summary`、`diagnostics bundle` 的职责边界，继续只消费 CLI/Core JSON facts，不解析 stdout，也不重新解析 PBW/PBT/PBL。
3. 新增 docs/spec/skill 治理 lint，阻断当前文档出现已发布版本状态回退、当前正式版本回退到历史版本、blocked 退出码误写、或把 PowerShell wrapper / SharpIDE 描述成业务规则承载层。
4. release engineering 规则继续向共享 PowerShell helper 收口；发布脚本保留编排职责和兼容 wrapper，不改变 release/tag guard 的行为。
5. Toolkit sync 开始把高变更文档模板文件化；未文件化的 skill/template 仍由同步脚本管理，后续版本继续降低脚本内嵌文本比例。

## 使用边界

3.4.0 不改变外部项目日常入口。维护类判断仍优先使用 CLI/Core 原生命令：

```powershell
pbbridge project health --project-root .
pbbridge project adoption check --project-root . --profile standalone
pbbridge diagnostics summary --project-root .
pbbridge diagnostics bundle create --project-root .
pbbridge contract validate .\.pbbridge\diagnostics-summary.json
```

PowerShell wrapper 仍只负责 runtime 定位、CLI 参数转发、日志落盘、JSON/退出码透传；`AllowBlockedResult` 只表示保留 blocked JSON，不改变 exit 10 的业务阻断语义。

## 发布检查

发布 3.4.0 必须确认：

1. 当前非 archive 文档、OpenSpec specs、Toolkit docs/skills/templates 和 `docs/pb9-ai-bridge` 历史入口通过 docs/spec/skill 治理 lint。
2. `pbbridge schema show` 与 `pbbridge contract validate` 的 v3 JSON 形态没有漂移。
3. release engineering summary、Toolkit manifest、runtime contract 和发布资产仍与目标版本一致。
4. `reference-pbl/PbdViewer` 既有脏状态不被本轮提交或回退。

## 非目标

本版不是写回支持矩阵扩容版本；不把 ORCA candidate 升级为 supported，不新增未准入写回路径，也不把 SharpIDE 或 PowerShell wrapper 变成 PowerBuilder 业务规则引擎。
