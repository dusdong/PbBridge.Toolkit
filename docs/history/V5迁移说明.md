# V5 迁移说明（历史归档）

> 本文只记录当时的迁移背景。当前版本不提供 V4/V5 输入兼容层，旧 JSON 必须重新运行 V6 DryRun 生成。

从 V4 升级到 V5 后，日常写回应改用 `pbbridge-delivery-close-loop.ps1` 或 `pbbridge delivery close-loop`。

保留入口：

1. `writeback close-loop`：专家排查 V4 close-loop、session cache 或底层结果映射。
2. `writeback object`：单对象写回失败后的对象级诊断。
3. `import-object` / `import-objects` / `import source`：底层 adapter、人工计划或新增对象排障。

迁移步骤：

1. 更新 Toolkit 到最新版。
2. 日常升级反馈运行 `scripts/pbbridge-toolkit-upgrade-check.ps1`（默认 `-WrapperSmokeScope recommended`），正式验收运行 `pbbridge toolkit upgrade-check --project-root . --wrapper-smoke-scope all`；结果中 `performanceSummary.totalElapsedMs` 是墙钟耗时，`wrapperSmokeTimings[]` 用于定位慢 wrapper。
3. 如果 `upgradeReadyToCommit=true`，按 `upgradeOwnedChanges[]` 提交模板、项目参数保留或 submodule 指针即可。
4. 如果 `blockingTemplateChanges[]` 非空或 `upgradeCompletionVerdict=requires-template-merge`，先处理阻断模板差异。
5. 如果 `requiredTemplateChanges=0` 且 verdict 为 `needs-git-hygiene` 或 `requires-git-hygiene`，优先读取 `blockingGitHygieneChanges[]` 判断是否是 AGENTS、业务 submodule 或其他 git hygiene 阻断。
5. 使用 V5 delivery 重新生成 DryRun / Apply / IDE evidence。

DryRun 后优先读取 `pendingApplyObjectCount` 和 `notWrittenObjectCount`；未写回不再代表 `failedObjectCount`。Apply 后优先读取 `deliveryVerdict`、`sourceMatchesObjectCount`、`ideChecklistCommand` 和 diff 计数。
