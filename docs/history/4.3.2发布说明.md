# 4.3.2 发布说明

`4.3.2` 是 v4 写回事实判断热修版本，重点解决 Apply/recover 后“已写入但被格式差异误判失败”的场景。

## 修复范围

1. `targetObjectWritebackVerdict` 新增 `written-format-only-drift` 和 `written-business-differs`，保留旧 `written-differs` 兼容值。
2. 统一内容归一化：CRLF/LF/CR、文件末尾换行和每行尾部空白不再算业务 drift。
3. Apply/recover/re-export 规范化后一致时，顶层输出 `status=applied`、`writebackVerdict=applied`、`pblWritebackCount>0`。
4. 仅格式差异视为可进入 IDE Full Build 的成功类结论，但必须输出 warning。
5. 真实正文、属性值、成员顺序或 SQL 语义差异输出 `written-business-differs`，不计入 `pblWritebackCount`。
6. 过期 DryRun 阻断统一使用 `PREFLIGHT_FACTS_STALE`，compact summary 直接提示漂移字段和重新 DryRun。
7. `diagnostics summary --result <v4-json>` 汇总对象写入、PBL 变化、normalized diff 和 IDE Full Build 建议。

## 判断规则

调用方优先读取 `targetObjectWritebackVerdict`：

- `written-matches-source`：对象已写入且规范化后与当前源码一致。
- `written-format-only-drift`：对象已写入，仅存在行尾、换行或尾部空白差异，可进入 IDE Full Build。
- `written-business-differs`：对象写入后反导存在业务差异，不可交付。

`PREFLIGHT_FACTS_STALE` 表示 Apply 使用的 DryRun 已过期，应重新运行 DryRun，而不是继续复用旧 facts。
