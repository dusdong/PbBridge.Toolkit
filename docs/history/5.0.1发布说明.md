# 5.0.1 发布说明（历史归档）

`5.0.1` 是 V5 交付体验与对象身份修复版本。它不扩大 PB9/PBSpy/PBSDK/ORCA 支持矩阵，重点是把共享库对象写回、V5 DryRun 解释和 PowerScript 源码预检收口到更稳定的生产契约。本说明已纳入 5.0.1 发布后补丁；版本号仍保持 `5.0.1`，不新增 `5.0.2`。

## 关键变化

1. 公共 `ObjectKey` 破坏性升级为路径化格式：`<workspace-relative-pbl-path>:<object-type>:<object-name>`，例如 `pb-libs/Lib_Query.pbl:userobject:nvo_query`。
2. 对象定位、写回、delivery close-loop、manifest 查询和 target PBL 解析统一使用 manifest resolver，不再按 PBL 文件名拼接 workspace 根目录。
3. `object find` 的唯一候选 `nextCommand.command` 输出可直接复制的 V5 写回命令：`pbbridge delivery close-loop --object <path-key>=<sourcePath>`。
4. V5 delivery full JSON 和 compact summary 新增 `canApply`。DryRun 通过但尚未写回时，`deliveryVerdict=dryrun-only`、`status=noop`、`canApply=true`、`canProceedToIdeFullBuild=false`。
5. V5 full JSON 与 compact summary 均输出 `blockedItems[]`，最多列出前三个阻断摘要项：`objectKey`、`stage`、`code`、`lineNumber` 和 `nextAction`；成功时固定为空数组 `[]`，不得为 `null`；`humanSummaryText` 在 blocked 场景追加 `top blockers`。
6. `canProceedToIdeFullBuild` 语义不变，只表示 Apply 后可进入 PowerBuilder IDE Full Build 验收；不得把 DryRun 阶段的 `false` 解读为验证失败。
7. source preflight 的 PowerScript 字符串扫描改为状态机，正确识别 `~"`、`~'`、`~~`、`~r~n`、单双引号字符串和字符串内 `//`。
8. source preflight 只有 `severity=error && confidence=high` 才计入 `BlockingDiagnosticCount`；medium confidence 诊断只能作为 warning/diagnostic，不得硬阻断 V4/V5 DryRun。
9. V5 schema show、schema explain、contract validate、handoff-summary、contract examples 和 Toolkit 文档同步输出并解释 `canApply` 与 `blockedItems[]`。
10. 清理发布候选中的旧 autonomous certification sample package 跟踪文件；这些样例证据不再作为 5.0.1 当前发布事实源提交。
11. 发布后补丁修正 `CODEX-START.md` 旧 ObjectKey 文案，release lint 会阻断 `<library-file-name.pbl>`、`ObjectKeyAliases` 作为公共入口和 `canonical <pbl-file>` 等旧规则残留。
12. `.pbbridge/evidence-supersession/` 默认归类为 `local-only-ignore`；`pbbridge git hygiene suggest --result <json>` 的 `suggestCommit[]`、`suggestIgnore[]`、`needsManualReview[]` 已破坏性收敛为结构化对象数组，元素包含 `path/statusLine/classification/reason/recommendedAction`。
13. `pbbridge delivery handoff-summary --result <v5-json>` 增强 `modifiedObjects[]`、`writtenPbls[]`、`sourceMatchSummary`、`ideNextAction`、`evidenceToKeep[]`、`localOnlyDoNotCommit[]`、`gitHygieneResultJsonPath` 和 `formatNoiseSummary`，用于 Codex/人工交接；`evidenceToKeep[]` 会过滤项目根、workspace 根、磁盘根和 `.pbbridge/` 根等过宽 evidence path。
14. delivery/readonly-sync summary 对 EOF newline、line ending、trailing whitespace 和 index-only 噪声只做 warning-only 解释；readonly-sync/project-health 遇到既有 PBV076 时会提示“全量健康 blocked 不等于目标对象 V5 close-loop 不可继续”。
15. `scripts/pbbridge-toolkit-update.ps1 -Apply` 使用分离 stdout/stderr 的 Git 调用，只按退出码判定失败；`Previous HEAD position ...` 等 Git 普通提示不再导致误 blocked。

## 升级要求

1. 升级后重新运行 `pbbridge workspace readonly-sync` 或 `pbbridge source export`，确保 manifest 中的路径化 `ObjectKey` 是当前事实源。
2. 自动化、脚本和 Codex skill 必须传递完整路径化 key；`Lib_Query.pbl:type:name` 只表示根目录 PBL，不再表示按文件名全局查找。
3. DryRun 后判断能否继续 Apply 时读取 `canApply`、`pendingApplyObjectCount` 和 `blockedItems[]`，不要从 `status=noop` 或 `canProceedToIdeFullBuild=false` 反推失败。
4. 被 source preflight 阻断时优先读取 `sourceDiagnostics[].confidence`、行号和建议动作；medium confidence 项需要人工确认，但不应阻断写回闭环。
5. Apply 后优先运行 `pbbridge delivery handoff-summary --result <v5-json>` 生成交接摘要，再运行 `pbbridge git hygiene suggest --result <json>`；`.pbbridge/local/`、`.pbbridge/cache/`、`.pbbridge/evidence-supersession/` 默认不提交。

## 不变边界

1. 不扩大 PB9/PBSpy/PBSDK/ORCA 支持矩阵。
2. 不把 PBSpyORCA candidate 升级为正式 supported 写回路径。
3. 不替代 PowerBuilder IDE Regenerate、Full Build、调试和业务运行验收。
4. 不承诺跨 PBL 原子事务；跨 PBL feature 继续只提供 batch 级恢复证据和 feature-level 交付结论。
