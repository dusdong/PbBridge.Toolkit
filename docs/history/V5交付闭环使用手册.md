# V5 交付闭环使用手册（历史归档）

> 本文仅用于解释历史结果。V4/V5 JSON 不再接受兼容读取；继续操作前必须重新运行 V6 DryRun。

V5 日常主路径是 `pbbridge delivery close-loop`。不要再在 `import-object`、`import-source`、`writeback object`、`writeback close-loop` 多个入口之间人工判断。

```powershell
pbbridge delivery close-loop --object app.pbl:window:w_main=src/app/w_main.srw
pbbridge delivery close-loop --object app.pbl:window:w_main=src/app/w_main.srw --object app.pbl:datawindow:d_main=src/app/d_main.srd
pbbridge delivery close-loop --object app.pbl:window:w_main=src/app/w_main.srw --apply
powershell -ExecutionPolicy Bypass -Command "& '.\scripts\pbbridge-delivery-close-loop.ps1' -Object @('app.pbl:window:w_main=src/app/w_main.srw','app.pbl:datawindow:d_main=src/app/d_main.srd')"
pbbridge delivery ide-checklist --result <v5-json>
pbbridge delivery ingest-ide-log --result <v5-json> --log <ide-full-build.log>
pbbridge delivery handoff-summary --result <v5-json>
pbbridge schema explain delivery-close-loop
```

PowerShell wrapper 的多对象参数必须通过 `powershell -Command` 传数组，例如 `-Object @('obj1','obj2')`。不要在 `powershell -File` 下使用 `-Object obj1,obj2` 或重复 `-Object`；CLI 原生命令才使用重复 `--object`。

优先读取这些字段：`deliveryVerdict`、`canProceedToIdeFullBuild`、`canApply`、`requiresManualRecovery`、`businessDiffCount`、`formatOnlyDiffCount`、`writtenObjectCount`、`sourceMatchesObjectCount`、`failedObjectCount`、`notWrittenObjectCount`、`pendingApplyObjectCount`、`blockedItems[]`、`ideChecklistCommand`、`nextCommand`、`objects[].recoveryState`、`pblBatches[]` 和 `performanceSummary`。`blockedItems[]` 在 full JSON 与 compact summary 中同源输出；无阻断时固定为空数组 `[]`。

Apply 后建议立即运行 `pbbridge delivery handoff-summary --result <v5-json>`。交接摘要会直接输出 `modifiedObjects[]`、`writtenPbls[]`、`sourceMatchSummary`、`ideNextAction`、`evidenceToKeep[]`、`localOnlyDoNotCommit[]`、`gitHygieneResultJsonPath` 和 `formatNoiseSummary`。`evidenceToKeep[]` 只保留具体证据文件或明确结果文件，自动过滤项目根、workspace 根、磁盘根和 `.pbbridge/` 根等过宽目录；若发生过滤，`handoffSummaryText` 会提示 `filteredEvidencePathCount`。`localOnlyDoNotCommit[]` 默认包含 `.pbbridge/local/`、`.pbbridge/cache/`、`.pbbridge/evidence-supersession/`；只有项目有明确审计归档策略时，才人工提交 supersession sidecar。

提交前建议运行 `pbbridge git hygiene suggest --result <json>`。`suggestCommit[]`、`suggestIgnore[]` 和 `needsManualReview[]` 都是结构化对象数组，每项包含 `path`、`statusLine`、`classification`、`reason` 和 `recommendedAction`；`--json` 结果路径别名已删除；写入完整 JSON 请使用 `--result <json>`。readonly-sync 的 `formatNoiseSummary` 只做 warning-only 解释，遇到 EOF newline、line ending、trailing whitespace 或 index-only 噪声候选时，先按 `refreshIndexCommand=git update-index --refresh` 复核，不要直接混入业务 diff。

V5 可以跨 PBL 自动分批并输出 feature-level 结论，但不承诺跨 PBL 原子事务。每个 `pblBatches[]` 都应读取 `batchApplyState`、`batchCanContinue`、`batchRequiresIdeFallback` 和 `batchRecoveryCommand`。Apply 后仍必须由 PowerBuilder IDE 执行 Regenerate / Full Build / 运行验收。

如果全量 `readonly-sync` 或 `project-health` 因既有 PBV076 blocked，不要自动推断目标对象 V5 close-loop 不能继续。对象级交付仍以 `deliveryVerdict`、`canApply`、`blockedItems[]` 和对象级 `recoveryState` 为准。
