# 3.11.1 发布说明

`3.11.1` 是 `3.11.0` 的 PBT 编译上下文热修版本。它不引入 v4 schema，也不扩大 PB9/ORCA 支持矩阵；重点修复外部项目在 `compileContextMode=pbt` 下使用 `ExcludeLibrary` 时，PBT `LibList` 中的只读 PBL/PBD 依赖被误判为“源码过滤范围”而没有进入写回编译上下文的问题。

## 主要变化

1. `pbbridge workspace readonly-sync` / export 继续让 `ExcludeLibrary`、`IncludeLibrary` 只影响源码事实源 `manifest.libraries[]` 与 `.sr*` 导出；`manifest.compileLibraries[]` 必须完整保留 PBW/PBT `LibList` 中的编译依赖。
2. `.pbw + all-targets` 场景保持扫描根目录所有 `.pbt`，并把 PBT 中出现的只读 PBL 和 companion PBD 纳入 `compileLibraries[]`，例如 `pb-libs/Lib_Object_try.pbl`、`pb-libs/canvas.pbd`、`pb-libs/pbdom90.pbd`。
3. import/writeback 在默认 `--compile-context pbt` 下继续以 manifest 为事实源构造 PBSpy `finalLibraryList`：目标 PBL 必须第一，后续按 PBT 顺序追加依赖并稳定去重。
4. scratch preflight 仍只复制目标写回 PBL；只读 PBL/PBD 编译依赖保持原路径引用，避免把外部共享库误纳入 scratch baseline。
5. diagnostics bundle 在 `CompileEntryImport -11` 且缺编译依赖时，会把 `missingCompileDependencies[]` 作为行动建议事实源，避免 `Illegal data type` 只停留在 PBSpy 原始错误文本。
6. 项目模型会把只在 `compileLibraries[]` 中出现的 PBL/PBD 暴露为只读编译依赖，PBL 使用 `readonly-compile-dependency`，PBD 使用 `companion-pbd`，方便外部项目审计 dependency summary。

## 推荐升级动作

已经使用 `3.11.0` 的外部项目建议升级到 `3.11.1`，然后重新执行 readonly sync 与目标对象 Apply smoke：

1. 更新 `.pbbridge/PbBridge.Toolkit` 到 `3.11.1` 快照并提交 submodule 指针。
2. 重新运行 `pbbridge workspace readonly-sync` 或模板脚本 `scripts/pbbridge-readonly-sync.ps1`。
3. 检查导出 manifest：`compileLibraries[]` 应包含 PBT `LibList` 中的只读 PBL/PBD，即使这些路径匹配 `ExcludeLibrary`。
4. 重新运行一次 `import-object --apply` smoke，检查结果 JSON 的 `compileContextMode=pbt`、`finalLibraryList[]` 和 `missingCompileDependencies[]`。

## 历史兼容说明

本版是 patch/hotfix，不改变 V3 主 schema、compact stdout 策略、`import-object` / `import-objects` 语义或 blocked exit code。历史 3.11.1 中 `managed-only` 仍作为显式兼容模式保留；当前 5.0.1 已拒绝该旧输入，日常写回应使用 V5 `delivery close-loop` 和 `--compile-context pbt`。
