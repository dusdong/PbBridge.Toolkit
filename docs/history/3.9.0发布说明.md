# 3.9.0 发布说明

`3.9.0` 是 V3 写回治理增强版本。核心变化是新增同 PBL 多对象批量写回入口 `import-objects`，并在模板迁移和共享库 evidence 初始化上加强项目参数保护与可操作提示。

## 主要变化

1. 新增 `pbbridge import-objects`，支持重复 `--object` 或 `--object-list`，默认仍输出 `pbbridge-v3-compact-summary`，完整事实写入 `resultJsonPath`。
2. 同一目标 PBL 的多对象写回共用一次 filtered diff、scratch PBL preflight、真实 Apply 和 post-apply review；检测到多目标 PBL 时默认 blocked，并提示拆分批次。
3. 结果 JSON 新增 `schemaName=pbbridge-v3-import-objects`、`objectResults[]`、`pblBatches[]`、聚合计数、timings、diagnostics bundle 路径和 rollbackPlan。
4. 模板迁移检测到 PBW、WorkspacePath、ProjectRoot、ScanScope、IncludeLibrary、ExcludeLibrary 等项目化参数差异时默认保留目标项目参数；无法可靠保留时 blocked，不用模板占位值覆盖项目配置。
5. shared-library 初始化脚本会在没有 `.gitmodules` 元数据时扫描 `pb-libs`、`pb-langchao` 等常见共享库目录，并生成 `.pbbridge/shared-libraries.init.json` 草案和 nextActions。

## 推荐用法

日常业务 `.sr*` 修改优先固定为：

```text
import-object/import-objects DryRun -> Apply -WriteBack -> 查看 resultJsonPath -> PowerBuilder IDE Full Build
```

存在未确认业务 `.sr*` 时，不建议随手跑全量 `readonly-sync`，避免 PowerBuilder 反导出噪声与业务改动混在一起。

## 兼容说明

本版不引入 v4 schema，不改变 `import-object` 既有行为，不扩大 PB9/ORCA 正式支持矩阵，不自动修复业务源码或 PBL。跨 PBL 原子批量写回不在 3.9.0 范围内。
