# 4.3.1 发布说明

`4.3.1` 是 v4 `writeback object` Apply 闭环热修版本，不扩大 PB9/PBSpy/PBSDK/ORCA 支持矩阵，也不移动已经发布的 `v4.3.0` tag。

## 修复范围

1. `writeback object --apply --preflight-result <writeback-object-dryrun.json>` 必须能消费外层 DryRun full JSON，并跟随 `importResultJsonPath` 到底层 `pbbridge-v4-import-source` facts。
2. `import-source/import-object/import-objects` Apply drift guard 只读取 DryRun JSON 中的 `sourceFactSet` 必要事实，不反序列化整个历史结果对象。
3. 数组根、schema mismatch、compact summary 缺 `resultJsonPath` 或旧字段形态不兼容时，统一返回 v4 可诊断错误，不泄漏 `.NET JsonElement Object/Array` 异常。
4. 已有对象的 `import source` action 判定必须稳定为 `modify` 或 `noop`；只有 manifest/current/state 投影均不存在时才允许 `add`。结果 evidence 输出 `targetResolution=canonical-key|short-key+pbl|source-path+pbl|state-source+pbl|type-name+pbl|new-object`。
5. Apply 失败、后处理失败或 post-review 失败后，只要目标 PBL hash/timestamp 变化，高层 `writeback object` 必须尝试对象级 recover/re-export；反导与源码一致时输出 `targetObjectWritebackVerdict=written-matches-source`。

## 使用建议

日常仍优先使用高层入口：

```powershell
pbbridge writeback object <pbl-file>:<object-type>:<object-name> --source <sr-path>
pbbridge writeback object <pbl-file>:<object-type>:<object-name> --source <sr-path> --apply --preflight-result <writeback-object-dryrun.json>
```

判断真实状态时优先读取 `targetObjectWritebackVerdict`、`writeBackAppliedState`、`targetPblChanged`、`reExportReviewVerdict` 和 `pblWritebackCount`。`status=failed|blocked` 不一定表示对象没有进入 PBL；如果 `targetPblChanged=true`，必须结合 recover/re-export evidence 判断是否还需要 IDE Full Build 或人工确认。
