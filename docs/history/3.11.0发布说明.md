# 3.11.0 发布说明

`3.11.0` 是 V3 批量写回吞吐与诊断确定性版本。核心变化是让 `import-objects` 在合法同 PBL 批量路径中更快、更可解释，并让 diagnostics summary 能直接消费批量写回完整 JSON facts。

## 主要变化

1. `import-objects` non-blocked 路径对逐对象 body diff 和 object fact 构建使用限流并行，输出顺序仍按输入对象和既有 batch 排序保持稳定。
2. `objectResults[]` 新增 `targetLibraryId`、`targetResolutionSource`，`pblBatches[]` 新增 `targetResolutionSources[]`，解析来源固定为 `target-entry`、`target-library-id`、`source-library-id`、`step-target-pbl-path` 或 `unresolved`。
3. batch artifact hash 对 objectKey 输入顺序和大小写不敏感；文件名前缀继续保留当前命令首个对象短名，便于人工识别。
4. `import-objects` 会写出专用 diagnostics bundle，索引主结果、plan、diff、DryRun、preflight、Apply、shared-library gate 和 underlying import diagnostics；blocked 结果也保留可报告证据。
5. `diagnostics summary` 读取 `pbbridge-v3-import-objects` 完整 JSON 时，会输出 target PBL batch 数、unresolved object 数、resolution source 摘要，并复用 `nextCommand` / `nextActions[]` 作为后续动作。

## 推荐用法

历史 3.11.0 的同一目标 PBL 多对象写回曾优先使用 `import-objects`；当前日常写回主路径已收敛为 `delivery close-loop`，`import-objects` 仅保留为专家排障和底层编排入口。排查 blocked 或跨 PBL 场景时，优先读取完整 `resultJsonPath`、`objectResults[]`、`pblBatches[]` 和 diagnostics bundle，不解析 compact stdout。

## 兼容说明

本版不引入 v4 schema，不改变 `import-object` 单对象语义，不开放跨 PBL 原子写回，不扩大 PB9/ORCA 正式支持矩阵。新增 JSON 字段均为 additive optional。
