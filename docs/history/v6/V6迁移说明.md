# V6 迁移说明

`6.0.0` 是破坏性升级，不提供 V4/V5 delivery JSON、旧字段别名或旧 preflight result 的兼容读取。

## 必做迁移

1. 更新 Toolkit 到 `6.0.0`，核对 `VERSION`、`manifest.json`、runtime CLI 与 external template version 一致。
2. 用 `pbbridge delivery close-loop --object <object-key>=<source-path>` 重新执行 V6 DryRun。
3. 将自动化改为读取 `pbbridge-v6-compact-summary.resultJsonPath`，完整事实读取 `pbbridge-v6-delivery`。
4. 使用嵌套 `apply`、`writeback`、`diff`、`conflicts`、`review`、`policy`、`recovery` 与 canonical `summary`，不再拼接历史结果。
5. 自动写回切换为 `--apply-if-eligible --policy <path>`；显式写回使用 `--apply --preflight-result <v6-dryrun.json>`。
6. IDE 交接改用 V6 `ide-checklist`、`ingest-ide-log` 与 `handoff-summary`。

## 旧输入处理

当 CLI 返回 `unsupported-schema-version`：

- 不修改旧 JSON 的 schema 标识；
- 不运行字段 mapper；
- 不从旧计数推断 V6 outcome；
- 升级 Toolkit 后重新运行 V6 DryRun。

历史 V4/V5 操作资料位于 `docs/history/`，仅用于审计和故障追溯。
