# 4.0.0 发布说明

`4.0.0` 是 PbBridge 写回契约硬切版本。import/writeback workflow 改为 `pbbridge-v4-*`、`schemaVersion=4`，并用 `applied|noop|blocked|failed|argument-error` 替代旧的泛化 `success`。

## 主要变化

1. `writebackVerdict` 成为写回必填事实，取值为 `not-requested|dryrun-only|applied|noop|blocked|failed|rolled-back|recovery-required`。
2. `rollbackVerdict` 成为 rollback 必填事实，摘要必须明确 “PBL 已恢复 / PBL 未恢复 / 需要人工处理”。
3. `applied` 只允许在真实 PBL 写回成功且 `pblWritebackCount > 0` 时输出；`pblWritebackCount=0` 必须是 `noop|blocked|failed`。
4. 新增 `pbbridge import source`，支持 `src 新文件 -> transient manifest -> DryRun -> Apply` 的新增对象快路径。
5. `import-object`、`import-objects` 和 `import-source` 统一以 `SourceFactSet` 作为事实源；顶层结果必须输出 `sourceFactSet`，object results 只能引用 fact set 中的对象、action、hash 和 target PBL facts。
6. DryRun 阶段执行 PBT/PBW LibList、manifest compile libraries、文件锁、staging 源副本、scratch PBL 导入/编译预检。
7. Apply 复用 DryRun facts；source、staging、manifest、target PBL、compile libraries、PBT/PBW 或 workspace/state root 漂移时直接 `blocked`。
8. ProjectionOnly 覆盖 `.sr*` 前保护本地改动；冲突写入 `.pbbridge/conflicts/projection/...`。
9. v4 Apply 成功后可写出 evidence supersession sidecar，说明同一目标 PBL 与对象的旧 failed/blocked/rolled-back 证据已被当前成功写回取代。

## 推荐升级动作

1. 更新 `.pbbridge/PbBridge.Toolkit` 到 `4.0.0` 快照并提交 submodule 指针。
2. 更新外部项目 wrapper，确保 `pbbridge-import-object.ps1`、`pbbridge-import-objects.ps1` 和 `pbbridge-import-source.ps1` 只透传 v4 JSON 与退出码。
3. 更新消费侧解析逻辑：只读 workflow 继续按 v3 common fields；import/writeback 必须读取 v4 `status`、`writebackVerdict`、`rollbackVerdict`、`pblWritebackCount` 和 `sourceFactSet`。
4. 对真实写回先跑 DryRun，再用 `--preflight-result <dryrun-json>` 执行 Apply，避免 Apply 使用漂移后的源码、manifest 或 PBL。
5. 如 PowerBuilder IDE 直接修改 `.pbl` 后只需刷新文本投影，继续使用 `pbl change-intake --projection-only`；完整发布前门禁仍回到 full intake。

## 兼容说明

本版硬切 v4 import/writeback 契约，不把 v3 import/writeback 作为稳定消费面保留。只读 workflow 可继续使用 v3。`4.0.0` 不扩大 PB9、PBSpy、PBSDK、ORCA candidate 或平台支持矩阵。
