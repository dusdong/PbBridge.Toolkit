# PbBridge.Toolkit 7.3.1 发布说明

7.3.1 是 7.3.0 的现场回归热修复。产品仍使用 V8 delivery schema 和 PB9/x86 写回边界，不引入 V9，也不改变冲突、快照、事实新鲜度和人工确认门禁。

## 修复

- R0006 先绑定 session 对象，再按 manifest entry `sourceRoot`、库级 `sourceRoot` 和兼容布局解析真实 `.sr*`。
- manifest 缺少 `members` 时，通过 PB9 成员定位端口解析唯一闭合的函数或事件实现；prototype、重载、未闭合成员和对象重名不参与猜测。
- 映射前校验路径未逃逸、源码存在且哈希未漂移；V8 IDE log entry 可输出 `mappingEvidenceSource` 和 `mappingReasonCode`。
- `verificationStatus=failed` 只表示日志存在编译或运行错误，与 `mappingStatus` 是否成功分开表达。
- 模板迁移 Plan/Decide 输出可复制的完整 Apply 命令，固定恢复 `ProjectRoot`、`WorkspaceId`、`PbwPath` 和 `PlanHash`；`-WhatIf` 会完成预检和审计但不安装项目文件。
- upgrade-check 将升级完成度和 Git 人工确认拆开：模板已对齐而仅剩 Git 项时为 `status=warning`，`upgradeCompletionVerdict` 只使用 `complete|ready-pending-commit` 表达完成度。
- 当前协作模板统一改为 V8 preflight、continue 和 session handoff；过期 Delivery 手册与 IDE 指南已从当前分发移除，历史行为通过 Git 追溯。

## 保持不变

- `schemaVersion=8`，已有 V8 session 不要求迁移。
- PB9 Full Build、GUI 调试、运行场景和业务正确性仍由 PB IDE 与验收人员负责。
- PERF 业务日志比较器、证据生成项目文档和 GUI Full Build 自动化继续延期。

## 发布门禁

候选包必须通过 .NET、Pester、OpenSpec strict、Toolkit lint 和打包后 Windows x86 doctor。正式签署还必须完成两个现场项目的同 session 回归：

- 餐饮项目把 `wf_validate_yydj_relation` 局部第 29 行映射到 `cy_qt.pbl:window:w_qt_jd2bz` 的真实 `.srw` 第 255 行，并证明写回范围和运行产物新鲜度。
- Hangjia 项目在同一 session 中保存 `cy.exe` 包装、旧 PBD 分类、插件目录、SHA256、x86 架构、deployment 和 handoff 证据。

任一现场门禁缺失时只能发布候选包，不得签署 7.3.1 正式版本。
