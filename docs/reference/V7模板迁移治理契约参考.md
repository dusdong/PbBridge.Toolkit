# 7.6.0 模板迁移治理契约参考

本文描述 PbBridge 7.6.0 的模板迁移公共契约。它不修改当前 `pbbridge-v8-delivery` schemaVersion 8、PBL 写回策略或 PB9 支持矩阵。

## 1. 归属与双哈希

受管 PowerShell provenance 使用 schemaVersion 2，并为当前可重建模板记录：

- `rawSha256`：安装、回滚、漂移和完整性依据。
- `normalizedTextSha256`：只参与来源分类。
- `normalizationProfile=powershell-text-v1`：严格解码 UTF-8 及带 BOM 的 UTF-8/UTF-16/UTF-32，移除 BOM 表现差异并把 CRLF/CR 统一为 LF；保留其他空白、注释与最终换行。

无法安全解码时结果必须为 `normalization-unsupported`，只使用 raw hash，不得猜测 format variant。来源分类顺序固定为 `managed-current-exact`、`managed-known-exact`、`managed-known-format-variant`、`managed-modified`、`unmanaged`。

## 2. 可提交 migration policy

`.pbbridge/migration-policy.json` 使用 `pbbridge-template-migration-policy` schemaVersion 1。首版只允许 canonical 仓库相对文件路径的 `project-custom/preserve`：

```json
{
  "schemaName": "pbbridge-template-migration-policy",
  "schemaVersion": 1,
  "productVersion": "7.6.0",
  "files": [
    {
      "path": "scripts/move-pb-build-output.ps1",
      "ownership": "project-custom",
      "action": "preserve",
      "reason": "项目自定义 PowerBuilder 构建输出布局"
    }
  ]
}
```

policy 只声明长期归属，不能绕过 AST、共享 module、CLI 参数或推荐 wrapper help/smoke 兼容性检查。glob、目录豁免、路径越界、重复路径和模板覆盖动作必须拒绝。

## 3. Plan/Decide/Apply

```powershell
.\scripts\pbbridge-template-migrate.ps1 -Plan -WorkspaceId canyin
.\scripts\pbbridge-template-migrate.ps1 -Decide -PlanHash <hash> -DecisionPath scripts/move-pb-build-output.ps1 -Reason "已审阅并保留"
.\scripts\pbbridge-template-migrate.ps1 -Apply -ProjectRoot <repo> -ToolkitRoot <toolkit> -WorkspaceId canyin -PbwPath <pbw> -PlanHash <hash>
```

Plan 的 canonical `semanticPlan` 排除时间戳和本机绝对路径并生成稳定 `planHash`。Decide 首版只产生 `preserve-custom-and-continue`；相同决定幂等，冲突决定失败。Apply 在写入前重新验证源文件、配置、policy、provenance、目标模板、planHash 和 decision set；任何漂移都以零项目写入阻断。没有待决定文件时允许一次性 `-Apply`。

旧 `-AcceptReviewedCustomizations` 和 `.pbbridge/template-migration-ack.json` 不再具有兼容或放行语义。

## 4. schemaVersion 8 审计

迁移完整结果使用 `schemaName=pbbridge-v7-template-migration`、`schemaVersion=8`、`productVersion=7.6.0`。Plan 与 decisions 分别使用 `pbbridge-v7-template-migration-plan` 和 `pbbridge-template-migration-decisions` schemaVersion 8。

本机审计位于 `.pbbridge/local/migrations/`，包含 `plan.json`、`decisions.json`、`result.json`、`index.json`、candidate manifest、recovery manifest、staging 和 backup。审计只记录路径、hash、分类、动作、兼容性和恢复证据，不得包含源码正文、diff 正文或密钥值。

typed outcome 包括 `awaiting-decisions`、`ready-to-apply`、`applied-with-preserved-customizations`、`blocked-incompatible-customization`、`rolled-back` 和 `recovery-required`；重复输入完成验证且无写入时可以返回 `no-change` 等价完成态。

## 5. 门禁消费

release-check、project-health 和 toolkit upgrade-check 只读核对当前产品版本、planHash、decisionSetHash、policy hash、candidate/raw hash、workspace、目标模板和 preserved 兼容性。有效决定只解决文件归属；`awaiting-decisions`、决定过期、hash 漂移、不兼容或恢复未完成继续阻断。旧 ack 最多产生迁移指引，不能改变 blocked 或 severity。

V5.0.0/V5.0.1 无 V7 配置可以作为受支持的 legacy-origin；其中仍保留的 3.7.4 官方资产只有在不可变 Toolkit Git provenance 命中时才作为受管旧版处理。V7.0.0 至 V7.3.1 配置由单一集合验证并可直接迁移到当前版本。V5 官方单文件迁移入口必须命中历史 Git provenance 后才能升级为当前双文件组，未知自定义继续阻断。

仅有既存业务脏状态时，upgrade-check 的完成度为 `complete`、顶层可以是 `warning`，默认退出 0；`--strict-git-hygiene` 只把 warning 映射为非零退出码，不改变 JSON 分类。
