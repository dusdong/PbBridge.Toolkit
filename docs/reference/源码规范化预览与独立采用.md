# 源码规范化预览与独立采用

`object normalize-preview` 对一个 manifest 已唯一管理的对象生成隔离建议。它不修改原源码、PBL、共享依赖、baseline 或 session；预览本身不调用 Apply、promotion 或 recovery。最高功能资格、实际候选和原始日志见 本能力证据（父仓 openspec/changes/add-pbbridge-7-6-0-source-normalization-preview/evidence-index.md）。

```powershell
pbbridge object normalize-preview --repo-root C:\owned-example --workspace default `
  --object synthetic.pbl:userobject:n_norm `
  --source C:\owned-example\src\synthetic\userobject\n_norm.sru `
  --output-dir C:\tasks\new-normalization-preview
```

输出父目录须已存在，任务目录须全新。路径、manifest 归属和源码声明的对象名在复制前核验；现存输出、受管源码/状态/缓存/锁/恢复目录重叠、ADS/UNC、符号链接和 junction/reparse 不确定路径均拒绝。当前运行须为可验证的 PBSpy/PB9 win-x86；报告包含实际执行文件及实际载入 PBSpy、PB9 SDK、ORCA 模块的路径与 SHA256。设置进程级 `PBSPY_HOME`、`PB_HOME` 和 PATH 时应指向同一已确认 bundle；跨 bundle 载入会阻断，不能凭文件存在宣称已载入。

`preview.json` 使用 `schemaName=pbbridge-source-normalization-preview`、`schemaVersion=1`。状态为 `no-changes`、`preview-ready`、`review-required`、`unsupported` 或 `blocked`。退出码 0 表示前两种完成状态，其他已生成报告的结果退出 10；参数及复制前拒绝由普通 CLI 错误合同表达，不能当作已执行原生预览。

报告区分当前原始字节 S、实际隔离编译输入 C、本次成功反导 E、旧目标 PBL/对象快照 T、baseline 可用性和执行构建。`input/original/<原文件名>` 保存 S，`input/compile/<原文件名>` 保存 C，两者目录分开以避免文件名碰撞。C 只从 S 的完整原始跨度产生，`compileTransforms` 证明 S→C，最终建议再次独立证明 S→E。PB9/PBSpy 可保留输入块顺序，不能假定原生会自动重排。T、Git index 和旧 baseline 均不提供新业务代码。

首版支持唯一完整函数/子程序的签名顺序，以及完整归属的直接 menu type/create/destroy 组。对象另有嵌套/其他类型分区时，首版无法证明隐式函数/子程序所属类型，菜单对象也适用此限制；完整显式菜单组仍可独立证明。签名、正文、所属类型和未参与分区都必须守恒；重载、重复成员、未知顶层片段、不完整组、外部继承菜单、未知控件声明和菜单事件归属未证明时不给建议。成员重排采用整个原始跨度，不能使用“删掉所有空白”比较。

baseline 文件只记录存在性和哈希；`present-not-validated` 明确表示没有验证其业务有效性，也没有用其内容生成建议。原生诊断中的源码位置指向隔离的实际编译输入 C，发生块移动时不能将 C 的坐标直接标为 S 的绝对位置。

格式范围限于可证明的外部缩进/行末空白、普通空行和行尾处理。含字面量、注释或续行的行保留其文本；不闭合的字符串/注释/续行拒绝。建议保留原编码、BOM、单一 LF/CRLF 和 EOF 换行策略。GBK 必须能严格解码并回编码到同一字节，且 workspace 的 `projectEncoding` 确认 GBK；混合行尾、单独 CR、VT/FF/NEL/LS/PS 等额外行分隔符、不确定编码或有损转码不生成建议。

只有 `preview-ready` 存在 `suggested.sr*` 和 `adopt.patch`，`no-changes` 不生成补丁。`diff.txt` 是 UTF-8 可读差异；`adopt.patch` 是 `pbbridge-source-normalization-patch` schemaVersion 1 的 JSON 字节替换补丁，包含 `expectedOriginalSha256`、`suggestedSha256`、编码/BOM/行尾及 `suggestedBytesBase64`，不冒充可直接交给 git apply 的文本补丁。独立采用必须先重核原哈希，再解码并重核建议哈希，才能保存原样字节。报告列出块的所属类型、完整签名、原/反导跨度、内容哈希、原因、诊断、阶段耗时及原工作区/共享依赖前后文件和目录清单。正常、失败和取消都保留保护观察。相同输入及构建产生相同建议字节；观察时间、耗时和任务绝对路径属于独立观察信息。

建议及报告以新文件方式发布，ready 报告最后写入；发布失败会撤去本次已创建的建议文件并返回 blocked，不覆盖或删除冲突的未知文件/目录。采用是独立源码修改，须由项目所有者授权。先审阅 `diff.txt`、完整变换证据和新业务代码，再重核原哈希及建议哈希。以下仅是已授权合成副本中的显式示例，命令没有自动采用或 baseline 刷新入口：

```powershell
$preview = Get-Content C:\tasks\new-normalization-preview\preview.json -Raw -Encoding utf8 | ConvertFrom-Json
if ($preview.status -ne 'preview-ready' -or -not $preview.protection.unchanged) { throw 'Preview not ready' }
$source = $preview.inputs.originalSource.path
if ((Get-FileHash -LiteralPath $source).Hash.ToLowerInvariant() -ne $preview.inputs.originalSource.sha256) { throw 'Expired suggestion; regenerate preview' }
if ((Get-FileHash -LiteralPath $preview.suggestedSourcePath).Hash.ToLowerInvariant() -ne $preview.suggestedSha256) { throw 'Suggested bytes changed' }
# 先另存当前原字节，然后在已授权的样例副本中独立采用。
[IO.File]::Copy($preview.suggestedSourcePath, $source, $true)
```

改变源码后，旧 preflight 会因 `preflight-source-drift` / `staging-context-facts-drift` 拒绝继续。新预检使用当前源码重建事实及可信依赖计划；Apply 沿用现有候选比较、非目标守恒、锁、漂移、promotion 和反导门禁。可信依赖计划是 V8 preflight 内的 `dependencyPlan`，没有独立 `dependency-plan` CLI。需要依赖边时提供确切的 `--depends-on`，不将动态线索写成 trusted。
