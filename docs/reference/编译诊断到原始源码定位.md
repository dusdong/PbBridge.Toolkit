# 编译诊断到原始源码定位

当前开发源码为 7.6.0，V8 schemaVersion 仍为 8。诊断说明不改变 import、冲突、隔离、candidate verification 或 promotion 的裁决。

## 如何处理一次编译错误

1. 从完整交付结果 `objects[].sourceDiagnostics`、`delivery explain`、`delivery summary` 或 `delivery handoff-summary` 读取同一诊断。expert/debug 的 `import source` 与 `import object` 使用 `compileSourceDiagnostics`；原有 `sourceDiagnostics` 仍表示源码静态预检，含义不变。
2. 先看 `invocationId`、`stage`、`nativeFunction`、`ownership` 和 `objectKey`。`nativeReturnCode=-11` 与 `messageCode=C0051` 分开保留。PBSDK 有时把 C0051 放在格式化的消息文本内；`messages[].messageNumber` 和 `messageText` 保留原值，结构化消息码另行提取。
3. 仅当 `mappingStatus=mapped` 时使用 `snapshotPath:absoluteLine`。原生 `nativeLine/nativeColumn` 始终保留；当前支持组合不提供已证明的绝对列，`absoluteColumn=null`。
4. `currentFileStatus=stale-or-missing` 表示当前磁盘文件与编译时原字节不同，只能定位保存快照。修复另存为新输入，重新 preflight；不要复用旧失败的坐标跳到新文件，也不要把旧成功当作当前成功。
5. `ambiguous` 不选择重载、重复事件或重复跨度的首个命中；`unmapped` 保留稳定原因。两种状态的绝对行列均为空。原始输入、快照或实际编译字节缺失/哈希不符时，不继续声明映射可信。

## 完整证据

每条诊断的 `evidencePath` 指向完整有序 invocation 文档。摘要可能只展示前三条并明确标注截取；完整文档保留所有已捕获消息。`messages[]` 同时保存 CP936 解码原文与原始 callback 字节的 Base64；解码不完整或既有 64 KiB 单字段上限触发时标记 `partial`，不声称完整或建立映射。

每个实际 `sourceInputs[]` 记录传入 ANSI 字节 `bytesPath/sha256/encoding`、可读输入及成员候选。`sourceEvidence` 记录读取时原字节 `originalBytesPath/originalSha256/originalEncoding`、UTF-8 可读快照与独立哈希、原换行和 `inputOriginalLines`。逐行来源来自 parser 实际去除 export header/comments 和 binary suffix 的切片操作；不会对后来编辑的文件求 diff，不以总行数差猜坐标。输入字节与真实 ANSI marshalling 不一致、不可逆转码或未建立关系时保持 unmapped。

`nativeModules` 保存实际加载 PBSpy/PBSDK 的路径与 SHA-256。规则只针对已验证的 CP936、PBSpy 0.2.0.1 和指定模块哈希组合；源码文件编码与 callback 的 CP936 合同分开。`callbackStatus=no-callback`、`persistenceError`、原源码或编译输入保存错误、取消/异常分别记录。诊断不可用不会把 importer 失败变成成功。

## 已验证边界

具体候选及原始记录见 本变更证据索引（父仓 openspec/changes/improve-pbbridge-7-6-0-source-diagnostics/evidence-index.md）。以下为本包合成样例的支持边界，不能扩张为所有 PB9/PBSpy 调用或全版发行资格。

| 原生阶段 | 对象/成员 | 坐标基准 | 固定样例 |
| --- | --- | --- | --- |
| CompileEntryImport | 全局 function | 声明行为原生第 1 行 | CP936/CRLF：C0051 原生 3 → 原源码 8 |
| CompileEntryImport | window event | 声明行为原生第 1 行 | UTF-8 BOM/LF：C0051 原生 4 → 原源码 15 |
| CompileEntryImport | function 续行 | 物理行，声明行为第 1 行 | UTF-8/LF：C0051 原生 4 → 原源码 9 |
| CompileEntryImportList fallback | window event，明确 Object header 且输入唯一 | 声明行为原生第 1 行 | C0051 原生 3 → 原源码 14；目标归属与依赖输入分开 |
| StageDependencyImports | window 依赖 | unknown | 已执行且返回 0、无 callback；没有依赖错误坐标证据 |
| 其他对象/成员/运行时/代码页、file 坐标阶段 | 未验证 | unknown | 不承诺绝对行 |

生产样例实际加载 PBSpy、pbvm90、pbcmp90、pbdwe90 与 libjcc；pbcgr90 仅在副本中存在，生产样例未加载，不能伪称已加载。若调用方预加载它，还会核对指定哈希。普通组件测试中的 file/member 映射规则不是原生支持证据。

每条 `sourceDiagnostics.nextStep` 解释当次调用的诊断，保留首次失败后即使 fallback 成功也不改写它。当前 `nextAction` 则结合所属对象最终 importer 检查、当前 blockedItems、写回/反导覆盖作判断；两者都使用 `source-error`、`environment-blocked`、`manual-verification`、`unknown` 分类，不改变 V8 状态或准入。

同一对象首次编译 C0051、fallback 成功时，原错误/返回码/坐标保留，但当前动作不因此重复提示 fix-source。已核验写回及反导时提示 Full Build 或实际剩余验收；另一对象当前锁阻断提示处理锁，另一对象仍编译失败则保留源码修复动作。没有最终结果的旧记录不能推断恢复成功，尤其仅验证 importer availability 的 DryRun 成功不能抵消后来的原生错误。环境/文件锁及人工 Full Build、运行、业务验收不会生成源码行。原生编译成功仅证明对应编译阶段。

## 复验入口

`scripts/pb9-source-diagnostics/SourceDiagnosticsSeed.csproj` 是只创建新 C: 合成库和最小源码的 x86 seed factory；已有目录拒绝写入。它复用本仓 NativeRuntime 装载核验，不启动历史 formal runner。

`scripts/pb9-source-diagnostics/Invoke-SourceDiagnosticsValidation.ps1` 接收确切 CLI、seed、局部 runtime 和新的 C: 输出根，逐例保留函数、事件、fallback、续行及修复后新 scratch 预检。每例检查固定期望行、原始归属、原生返回码、实际 CLI 哈希和 seed PBL 未变；失败目录不覆盖。精确构建和复跑命令见本包交接。


依赖源码在真实 `LibraryEntryExport` 返回处保存原字节与解码文本，标记 `originalBytesOrigin=library-entry-export`；无法确认原文件路径时为空，不能继承请求目标的路径。单对象和列表输入引用同一份已保存依赖来源；依赖错误坐标仍未验证。

生成开发帮助资产时，`sync-toolkit-assets.ps1` 可显式使用 `-DevelopmentTaskOutputRoot <外部任务目录>`，并同时提供 `-DevelopmentRuntimeSourceRoot` 与 `-DevelopmentCliAssetsOnly`。输出必须位于该显式目录内；这仅解决任务本地 C: 输出约束，产物仍标记 `development-cli-assets-only-incomplete-distribution`，不能作为完整 Toolkit 来源采用。
