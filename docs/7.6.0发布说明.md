## 本包功能

`pbbridge delivery history --session-file <known-session.json> [--result <new-report.json>]` 仅接受已知 7.5.2/7.5.3 V8 session，生成 `pbbridge-delivery-history` schemaVersion 1。默认只向 stdout 输出，`summaryText` 说明本次查询成功与原交付结果的区别。历史交付失败也可查询成功。

保存报告时，先准备独立任务目录，再显式传入该目录中的新 JSON 路径。命令不会创建缺失父目录；现有文件、链接、受管 session/evidence/baseline/源码/PBL 位置及无法证明独立的路径均拒绝。记录工作区内仅允许既存 `.pbbridge/local/` 任务目录，仍拒绝其中受管名称的子目录。

输入快照用同一文件句柄读取，SHA-256 与解析使用同一组 bytes。`readerProductVersion` 是读取器版本，`recordedProductVersion`、`recordedProducerBuildIdentity` 和 `missingProducerIdentityFields` 描述原身份；缺失字段保持未知。`recordedAt` 来自原 updatedAt，`recordedCreatedAt` 来自 createdAt，`observedAt` 仅是本次观察时间。

`recordedWorkspace` 和 `recordedState` 原样保留原范围、状态及 recovery reference。原 verified/attested/failed/not-checked 不代表当前就绪；`currentEvaluationStatus=not-evaluated`、`reportMode=historical-read-only`、`canContinue=false`。附件路径、哈希、状态仅为原文，`evaluationStatus=not-rechecked`；缺失引用为 unavailable，不访问附件、网络、数据库或 PB 原生工具。

独立报告不属于当前 Delivery 证据。原旧 session 与报告均不能进入 continue、Apply、summary、explain、cleanup、IDE、attest、handoff、packaging、deployment 或 evidence ingestion。当前执行须重新生成当前 preflight/session；历史查询不修复 readonly-sync 冲突、不执行恢复、不写 locator/index/lock。

附件 `recordedType` 仅保留原 `type`，`recordedStatus` 仅保留原 `status`，两者独立。任一字段缺失或非字符串时，该报告字段省略，表示未知，不使用另一个字段补齐；路径、哈希和 `not-rechecked` 标记不因此改变。
