## 关键修复

- 从 target、`CompileLibraryPaths`、PBT/PBD/LibList、响应文件、工作目录和允许的路径型环境值计算 importer 可达路径闭包；按 Windows 文件 identity 去重，拒绝 reparse point、硬链接回指、路径逃逸和 identity 冲突。
- 在第一个短 `PblLockSet` 窗口重验 guard、建立 before baseline 并逐文件复制/哈希验证 staging；任一 setup 失败时 importer 调用次数为零。
- importer 只接触 staging 路径。staging 依赖副作用记录为 `isolated-compile-side-effect`，不得同步回原工作区，也不阻断有效 candidate。
- candidate manifest 验证计划对象全部匹配候选源码、整库对象 inventory 无计划外增删、全部非目标对象语义指纹不变。
- promotion 使用第二个完整 `PblLockSet` 协调遵守同一协议的 PbBridge 参与者，并在同一锁窗口内紧邻 `File.Replace` 重验目标及全部原依赖 guard；无删除后复制 fallback。
- `PblLockSet` 不承诺排除 PB9 IDE 或其他非协作写入者。不主动检查这些进程或要求关闭确认；锁占用、guard 漂移和平台原子资格不足均在 intent 前 fail-closed。取消进程前置条件不代表支持任意外部并发写入。
- replace 前原子持久化 promotion intent；重启/session 查询按 target before/candidate/other/missing/unreadable 与依赖哈希恢复裁决。只有 `recovery-required` 返回退出码 12 并展示绑定该 intent 的 `delivery rollback-promotion` 命令。
- 显式 rollback 在第二次完整 stale 检查通过后仅原子恢复有证据证明由本事务改变的目标；未变化或外部漂移的依赖不会被无意义覆盖。
- full、compact、session checkpoint 和 CLI nextAction 仅以可选字段扩展 V8；冻结且未重新编译的 7.5.1 reader 仍可忽略新字段并读取既有字段。

## 能力边界

- 目标必须是既有、非空 PBL；新 PBL、零对象库、新 application/bootstrap 和 application Painter 元数据仍由 PB9 IDE 人工处理。
- importer/candidate/promotion 哈希成功只证明隔离写回与物理落盘，不代表 PB9 Regenerate/Full Build、运行或业务验收通过。
- PB9 IDE、杀毒/备份工具或其他不遵守 `PblLockSet` 的写入者与 promotion 并发不受支持；普通 Windows 路径 API 不被包装成虚假的绝对排他租约。
- staging、candidate、promotion 和 recovery evidence 必须保存在 `.pbbridge/local` 或等价 local-only 根，不得进入提交。

## 升级与验收

当前运行时只接受由当前五元构建身份生成的 V8 preflight/session。旧远端 checkout、旧 Toolkit/runtime、旧 stdout JSON、旧 state 和非当前 Delivery/session 证据均不属于受支持写入输入；升级 Toolkit 后必须按 workspace 重新生成当前 V8 preflight/session。历史行为通过正式 Git commit/tag 与 replacement lineage 追溯，当前工作树和 Toolkit 包不再分发历史 Delivery 手册、reader 或兼容入口。

当前支持边界、删除/保留清单、golden 规范化规则与入口探测矩阵见 `docs/codebase/DELIVERY-CAPABILITY-BOUNDARY.md`。
