# PbBridge.Toolkit 7.4.0 发布说明

7.4.0 是决策驱动交付版本。它不扩大 PowerBuilder 自动化边界，而是把现有 Git、workspace、manifest、PBL、LFS、V8 session 与 IDE evidence 事实收敛成可复核的唯一决策：文件为什么脏、是否应提交、下一条安全命令是什么。

## 主要变化

- `pbbridge git governance --workspace <id>` 为每个路径输出唯一的 `commit`、`ignore`、`review`、`block` 或 `defer` 决策，并保留 reasonCodes、evidence 与 nextCommand。
- PBL drift 当前契约升级为 schemaVersion 4，分别表达 workspace ownership、Git LFS、精确 baseline SHA256、`.sr*` 关联、V8/IDE build evidence 与最终决策；不再使用 `binary-baseline-policy-present` 占位分类，也不自动断言 metadata-only。
- `hygiene check` 与 `hygiene fix --what-if` 检查本机会话、缓存、诊断、暂存、恢复和临时证据目录；7.4.0 不自动改写 `.gitignore`。
- V8 多对象 preflight 支持显式 `dependsOn`，并提取请求内可唯一定位的继承与直接静态调用作为 trusted edge；动态调用只作为 advisory。Apply 按可信拓扑执行，首个导入或反向复核失败、未知或部分成功后停止后续对象。
- trusted plan 纳入 facts freshness；continue 检测到 `dependency-plan-drift` 时在任何 PBL 写入前阻断。
- V8 session 增加对象级 execution checkpoint，并提供 `delivery summary`、`delivery explain --why-blocked` 与只读 `delivery cleanup --what-if`。
- target、workspace、ide-release 阻断分层表达；compact count 使用 evaluated/not-evaluated/failed，不再输出无解释的 `null`。
- PB9 Full Build 只有同时识别开始、完成、目标和零错误时才是 `verified`；截图只记录 SHA256 和 pending-review draft，不引入 OCR。

## 兼容与迁移

- V8 delivery 继续使用 schemaVersion 8，但旧的多对象 preflight 缺少 trusted dependency plan，必须重新预检后才能 Apply。
- 旧 PBL drift JSON 只允许历史查看和诊断，不能驱动当前 governance 或提交决策。
- PBL baseline policy 使用逐路径 `expectedSha256`；只有路径而没有哈希的旧条目不会被视为匹配基线。
- `git hygiene suggest` 与 `precommit-summary` 保留入口，但结论投影自同一 governance service。

## 明确不包含

- 通用 PowerScript 解析器、完整调用图或跨 workspace 自动依赖推断；
- 图片 OCR、截图自动判定编译通过；
- `delivery cleanup` 的真实删除模式或通用 retention engine；
- 为性能提前重写 Git plumbing。当前实现优先保证可解释性与正确性。

## 发布门禁

候选版本必须通过相关与全量 .NET、Pester、contract tests、OpenSpec strict、Toolkit 资产同步与 lint、win-x86 self-contained 发布构建，以及双 workspace、LFS、submodule、历史 PBV076 和 PB9 Writer→Direct 受控 fixture 回归。PB9 GUI Full Build、运行场景和业务正确性仍由 IDE 与验收人员完成；人工声明保持 `attested`，不会伪装为工具 `verified`。
